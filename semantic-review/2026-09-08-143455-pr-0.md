# Verified in-app browsing for 天天领现金 notes

The change adds a dedicated same-app state machine for the exact `天天领现金-浏览笔记` / `浏览任意一篇笔记` / `去参与` task and bypasses broad ignore rules for that supported schema. It waits for the cash page, scrolls, chooses a later two-column candidate row, verifies navigation, dwells for the parsed duration plus a margin, and backs out until `签到任务` is recognized. Hierarchy dumps and node-only card clicks fail closed, but page movement, card identity, and note opening are not proven strongly enough, and delayed work is not scoped to a run generation. Scope note: this directory has no `.git` metadata, so `git diff main` and base-branch checks were unavailable; the dedicated `DailyCash` symbols and related settings copy were treated as the change surface.

Watch for: **confirmed** full-page text signatures do not prove destination stability or physical scrolling; **confirmed** generic clickable geometry does not prove the first two actual note cards were skipped; **confirmed** note-open verification can accept an intermediate or unrelated in-app page; **confirmed** old callbacks can act in a restarted run because there is no run/task generation token; **confirmed** the state machine has no regression tests.

**Verdict**: NEEDS_CHANGES

## High-level view

Task recognition is narrow: `isDailyCashNoteTask` requires the exact trimmed title and action plus the expected description fragment, and `isIgnoredRow` applies its override before built-in or user skip matching. The settings copy matches this behavior by naming supported dedicated flows as exceptions to broad `去参与` skips.

**Confirmed:** task fields reset at run/package start and in `markCurrentTaskDone`, including manual stop, but completion neither cancels queued work nor advances a generation. A restarted run can recreate the same title and state while an old callback is still pending.

**Confirmed:** destination and scroll gates use `pageSignature`, which includes every exposed text value and vertical coordinate. Exact equality can reject a stable page with dynamic text, while inequality after the swipe can be caused by the same text changing without movement.

**Confirmed:** card candidates are generic clickable rectangles, not positively identified note cards. Selecting `rows[1]` skips one geometry-matched pair, not necessarily the first two notes.

The dwell calculation for a stated 15-second task is 20 seconds, including the five-second margin, and starts after two navigation samples. **Confirmed:** those samples only prove that the source marker disappeared and the hierarchy changed, so the timer can start on a loading shell or unrelated in-app page.

Return completion is gated on `签到任务` recognition before every bounded Back and only then records the task done. Inconclusive destination, scroll, card-grid, note-open, and final-return states dump bounded hierarchy data rather than use a coordinate guess.

## Dynamic cash content is treated as both instability and scrolling

`awaitDailyCashDestination` requires two identical `pageSignature` values (`LauncherAccessibilityService.kt:2830-2883`), while `pageSignature` contains every visible `text@top` pair (`lines 1937-1939`). **Confirmed:** a changing balance, countdown, rotating label, or lazy-loaded text resets `dailyCashDestinationHits` even when the destination is stable.

`awaitDailyCashScroll` accepts any non-empty signature different from the pre-scroll signature (`lines 2886-2920`). **Confirmed:** no anchor displacement is checked, so a text mutation can satisfy the scroll gate without movement. Compare stable header/card identities and require consistent vertical displacement across multiple anchors while ignoring volatile values.

## Two generic clickable rows do not establish note-card order

`findDailyCashCardRows` starts from every clickable node and filters by broad dimensions, position, and rejected text (`LauncherAccessibilityService.kt:2979-3038`). It requires no note marker, list-container ancestry, resource ID, image/title structure, or relationship to a note-section header. A pair of welfare or promotional controls can become row zero while the first note pair becomes row one.

`findAndOpenDailyCashCard` selects `rows[1].first()` (`lines 2933-2977`). **Confirmed:** this proves only that one geometry-matched pair precedes the target, not that the pair contains the first two notes. Require positive note-card identity before indexing the second row; otherwise retain the current forced dump and failure path.

There is no coordinate fallback for the selected card: candidates come from `collectClickableInWindow`, and `performClick` uses `ACTION_CLICK` when the node is present (`lines 1310-1327, 1631-1633, 2962-2972`). Candidate identity, not click dispatch, is the blocker.

## Hierarchy change is not positive note-open verification

`verifyDailyCashNoteOpened` accepts two samples when Ctrip remains foreground, `签到任务` and `天天领现金` are absent, and the hierarchy differs from the source (`LauncherAccessibilityService.kt:3045-3091`). **Confirmed:** loading shells, error pages, modals, and unrelated same-app routes meet those conditions; the two polls do not require the same destination hierarchy or note-specific evidence.

`planDwell` converts a stated 15 seconds to 20 seconds and starts timing after this gate (`lines 3749-3783`; `DWELL_SAFETY_MARGIN_SECONDS`, line 4422). **Confirmed:** if the gate accepts a transient shell, the required readable-note dwell is not guaranteed. Require a stable note author/title/body/media marker, known detail activity/view ID, or card-title handoff.

## Mutable state guards do not isolate delayed work across runs

`markCurrentTaskDone` clears dedicated fields (`LauncherAccessibilityService.kt:359-380`), and run/package startup clears them again (`lines 647-685, 772-804`). `finishTaskWithResult` removes only `watchdogTick` (`lines 4127-4158`); `postDailyCashPoll`, screenshot continuations, dwell, and return callbacks carry no run generation.

**Confirmed:** after stop, a new run sets `runActive=true`, clears the interruption flag, and can recreate the same title/state before an old callback fires. Increment an epoch on start, stop, package transition, and final completion; capture it in delayed work and reject mismatches. Centralize daily-cash clearing in task, package, and run completion paths.

## Requested invariants have no executable coverage

No unit or instrumentation test references `DailyCash`, `天天领现金`, dwell parsing, stale callbacks, or verified return. **Confirmed:** `./gradlew testDebugUnitTest --no-daemon` passes but executes only `ExampleUnitTest.kt`. Add focused state-machine tests for the issue list above and for completion only after `isOnTaskPage` succeeds.
