# Safer multi-card Unlike & Unfollow list recovery

The change turns Unlike & Unfollow into a bounded multi-card loop that remembers attempted cards, verifies each unlike once, and re-enters the liked list after every detail page. It carries the source card set into refresh verification and strengthens final-empty confirmation. The requested A/B progression and source-aware empty-list protections are present, but two exhaustion paths can still report completion before all source cards are reachable, and title-only identity can merge distinct cards. Scope note: this directory has no `.git` metadata, so `git diff main` and base-branch verification were unavailable; the multi-card state machine and its direct lifecycle helpers were treated as the review surface.

Watch for: **Medium, confirmed** stale-only non-empty content bypasses the intended one-time tab refresh; **Medium, confirmed** the cumulative 30-swipe cap can terminate without two unchanged swipes; **Medium, confirmed** duplicate normalized titles collapse into one attempted key; **Low, confirmed** the loop has no executable regression coverage.

**Verdict**: NEEDS_CHANGES

## High-level view

The return gate preserves `sourceListSignature` through normal polling and the refresh restart. An unchanged A/B return exposes B as unattempted, an A-removed/B-visible return exposes B directly, final empty is accepted only after six stable empty samples when the source contained no other card, and source proof of B prevents a temporary empty list from being reported as completion.

Attempt identity is inserted before the cover opens, and dispatch changes state before tapping the thumb-up control. Token/run/mode/state checks reject obsolete stages, and recursive return calls preserve the token, card, source signature, stability counters, and `refreshAttempted`; each attempted key can therefore dispatch at most once. Each return pass is about 13 seconds at the configured cadence, while `noteProgress` extends the 60-second watchdog, so the optional second pass is not at risk of watchdog termination.

The stale-A-only path waits for the bounded attempt count, but `boundedNonEmptyFallback` runs before the refresh branch and resumes scrolling immediately. The intended tab reselect is unreachable for exactly the stale non-empty condition it is meant to repair.

No-movement detection itself needs two accepted swipes that return the same attempted viewport. The separate cumulative `UNLIKE_MAX_LIST_SCROLLS` condition bypasses that evidence once 30 swipes have occurred anywhere in the run.

## Stale A resumes before the one-time 赞过 refresh

In `waitForLikedListAfterReturn`, a stable non-empty signature at `attempt >= UNLIKE_LIST_RETURN_ATTEMPTS` satisfies `boundedNonEmptyFallback` and returns to `settleAndDumpUnlikeUnfollow` before execution reaches the timeout block (`LauncherAccessibilityService.kt:2535-2571`). **Medium, confirmed:** for source A/B followed by a stale A-only return, `removed` and `unattemptedCount` are both false, but the attempt-24 fallback wins; `refreshAttempted` remains false and the one-time 赞过 reselect at lines 2575-2601 never runs.

If scrolling the partial view never exposes B, the loop can later report all reachable cards attempted. Move the bounded non-empty fallback after the one-time refresh decision, or permit it only when `refreshAttempted` is already true.

## The global swipe budget bypasses unchanged-viewport proof

Starting from a fresh all-attempted viewport, the first observation seeds `unlikeLastVisibleSignature`, then two accepted swipes increment `unlikeNoMoveScrolls` to `UNLIKE_NO_MOVE_SCROLL_CONFIRMATIONS` (`LauncherAccessibilityService.kt:2127-2163`). **Medium, confirmed:** exhaustion is also triggered by `unlikeListScrolls >= UNLIKE_MAX_LIST_SCROLLS`, and that counter is cumulative for the package rather than reset for each post-Back list generation (`lines 668-677, 2137-2147`). After 30 earlier swipes, a new all-attempted viewport completes immediately even if its signature changed and more cards remain below it. Keep the safety cap as a distinct stopped/partial outcome, or require the same two unchanged confirmations before describing the list as exhausted.

## Title-only keys merge distinct liked cards

`findLikedCardTargets` builds `key` from `title.lowercase()` and applies `distinctBy { it.key }` (`LauncherAccessibilityService.kt:2297-2304`). **Medium, confirmed:** two cards with the same normalized title become one target, and after that key is attempted every later card with the same title is treated as attempted. Use a stable card identifier when exposed, or combine title with persistent structural metadata that survives scrolling and refresh without collapsing separate cards.

## Multi-card invariants have no regression tests

Only `ExampleUnitTest.kt` and the placeholder instrumentation test exist. **Low, confirmed:** `./gradlew testDebugUnitTest --no-daemon` passes, but no test executes unchanged A/B, stale A plus refresh, A removal, strong final-empty confirmation, source-aware temporary empty handling, two-swipe exhaustion, cumulative swipe caps, duplicate titles, or at-most-once dispatch. Extract the return decision into a deterministic state reducer or add focused service tests with mocked nodes and handler timing.
